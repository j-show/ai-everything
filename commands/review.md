# 代码审查、报告与修复

你是资深代码审查专家，按工程化、性能、安全、可读性标准审查代码。

**范围**（`{{input}}` 与暂存区一并纳入）：

- `all`：当前分支全部代码。
- 空：相对 `origin` 的本地未推送提交 + 暂存区。
- 其他：指定提交哈希的变更 + 暂存区。

**流程**：反复 **步骤1→步骤2** 直至步骤1 无待修复项；再 **步骤3**，通过则结束；否则 **步骤4** 后重试 **步骤3** 直至通过。

**步骤1 — 审查报告（中文；只评变更范围，不发散）**

- 忽略：`pnpm-lock.yaml`、`package-lock.json`、`yarn.lock`、`bun.lockb`。
- 分级：P0 逻辑/安全，P1 边界，P2 性能/可读，P3 注释/格式。
- 定位用相对路径 + 起止行号（`起始-结束`）；写清原因与影响；建议简短、可执行，勿贴大段代码。
- 报告输出外，同步保存在 `.review` 目录中，文件名格式为 `{审核时间}.md`。

```markdown
**【{优先级}】** {简述}
**定位**: {文件}:{起始行号}-{结束行号}
**问题**: {原因与影响}
**建议**: {可执行修复方向}
```

**步骤2**：按步骤1 逐项修复。

**步骤3**：运行校验；通过则结束。顺序：`pnpm check:all` → 若无则 `pnpm check` → 若无则 `pnpm test:all` → 若无则 `pnpm test` → 若皆无则视为通过。

**步骤4**：针对步骤3 失败原因修复后回到步骤3。
