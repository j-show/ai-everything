# 测试 → 审查 → 文档（流水线）

按顺序调用已安装技能 **test-helper**、**review-helper**、**doc-helper**，完成测试对齐、代码审查修复与文档补全。

## 前置检查 ⛔ BLOCKING

执行任何步骤前，确认以下技能**已安装且本会话可调用**（以当前环境的可用技能列表 / Skill 工具为准）：

| 必需技能 | 用途 |
| -------- | ---- |
| `test-helper` | 步骤 1：按实现重写测试 |
| `review-helper` | 步骤 2：审查并修复代码 |
| `doc-helper` | 步骤 3：JSDoc、注释与 README |

**检测方式**：逐项核对上述 `name` 是否在可用技能中；不可通过「仓库里存在同名目录」推断已安装。

若任一缺失 → **立即退出**，仅输出：

```text
缺少已安装技能：<缺失名列表>
请先安装后再运行本命令（Cursor 插件市场，或 npx skills add …）。
```

不得在未安装时改测、审查或文档。

## 用户输入 `{{input}}`（审查范围）

本命令将下列快捷指令传给 **review-helper**（步骤 2）；步骤 1、3 可附带相同文本作目录提示，但不改变 review-helper 的范围表：

| `{{input}}` | 审查范围（步骤 2） |
| ----------- | ------------------ |
| `all` | 当前分支**全部**代码 |
| `{commit-hash}` | **指定 commit** 的变更 + **暂存区** |
| _(空)_ | 相对 `origin` **尚未推送的提交** + **暂存区** |

说明：

- 暂存区始终纳入步骤 2，除非用户在 `{{input}}` 中明确要求排除。
- `all` 前若改动面过大，可先向用户确认；确认后仍用 `all` 传给 review-helper。

## 原则（必须遵守）

- **只走已安装技能**：各步必须完整遵循对应技能的 `SKILL.md` 工作流，不得用仓库内 Markdown 路径代替技能调用。
- **顺序固定**：1 → 2 → 3；不得调换或跳过（除非用户明确要求只做其中某步）。
- **审查范围以表为准**：步骤 2 必须把解析后的范围显式交给 review-helper，勿自行扩大或缩小。

## 执行顺序

### 步骤 1 — test-helper

1. 调用已安装技能 **test-helper**，按其工作流执行（检索实现 → 契约清单 → 重写测试 → 验证）。
2. 若 `{{input}}` 为目录路径（非 `all`、非 hash），将该路径作为测试范围提示传给技能；否则按 test-helper 默认（全量或技能内约定）处理。
3. 步骤 1 完成且测试验证通过后，再进入步骤 2。

### 步骤 2 — review-helper

1. 调用已安装技能 **review-helper**。
2. 将 **审查范围** 设为上一节表格中与 `{{input}}` 对应的取值（`all` / hash / 未推送+暂存）。
3. 执行 review-helper 双循环：报告 → 修复（直至无待修项）→ 校验 → 失败则修复后重试校验。
4. 审查报告须符合 review-helper 约定（中文、P0–P3、`.review/{时间}.md` 落盘等）。

### 步骤 3 — doc-helper

1. 调用已安装技能 **doc-helper**，按其工作流执行（摸底 → JSDoc → 关键注释 → README → 自检）。
2. 优先对步骤 1–2 中改动过的模块补文档；用户若限定目录，则与 `{{input}}` 一致。
3. 遵守 doc-helper 的忽略目录与 README 中英规则。

## 向用户输出

流水线结束后简要汇总：

- 前置检查：三技能是否齐全（已检查时一句带过）
- 步骤 1：测试范围与结果（通过 / 失败说明）
- 步骤 2：审查范围、是否还有 P0–P1、校验命令与结果
- 步骤 3：文档更新范围（README / 哪些模块已补 JSDoc）

## 常见错误

| 问题 | 处理 |
| ---- | ---- |
| 未检测技能就执行 | 回到前置检查 |
| 用仓库 `skills/*` 代替调用 | 改为调用已安装技能 |
| 步骤 2 未传 `all` / hash / 空 范围 | 按上表解析 `{{input}}` 后重跑 |
| 审查未闭环就跑文档 | 先完成 review-helper 双循环 |
| 将 `{{input}}` 当成 test-helper 的 hash 范围 | hash 仅用于 review-helper；测试范围见步骤 1 |
