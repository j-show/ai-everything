# 按用户提示词创建 Skill，并审查至无改进建议

## 用户目标

根据 `{{input}}` 中的提示词，调用已安装技能 **skill-forge** 创建或更新一个完整技能，再调用 **skill-review** 审查该技能；仅根据审查报告 **Suggestions** 修复，并重复审查直到 **Suggestions** 中无待处理项。

## 前置检查 ⛔ BLOCKING

执行任何步骤前，确认以下技能**已安装且本会话可调用**（以当前环境的可用技能列表 / Skill 工具为准）：

| 必需技能 | 用途 |
| -------- | ---- |
| `skill-forge` | 步骤 1：创建或更新技能 |
| `skill-review` | 步骤 2–3：审查与按建议修复 |

**检测方式**：逐项核对上述 `name` 是否在可用技能中；不可通过「仓库里存在同名目录」推断已安装。

若任一缺失 → **立即退出**，仅输出：

```text
缺少已安装技能：<缺失名列表>
请先安装后再运行本命令（Cursor 插件市场，或 npx skills add …）。
```

不得在未安装时创建技能或执行审查。

## 原则（必须遵守）

- **提示词即需求**：`{{input}}` 是技能的功能、场景与约束来源；不得擅自替换为用户未提及的目标。
- **只走已安装技能**：各步必须完整遵循对应技能的 `SKILL.md` 工作流，不得用仓库内 Markdown 或目录路径代替技能调用。
- **Forge 全流程**：步骤 1 必须调用 **skill-forge**。
- **Review 专精审查**：步骤 2 必须调用 **skill-review**，审查对象仅为步骤 1 产出的**目标技能**（整个技能根目录，非全仓库）。
- **只改 Suggestions**：步骤 3 只落实报告 **Suggestions** 中的 What / Where / Fix；**Strengths** 仅供保留，不得因「锦上添花」扩大范围。
- **退出条件**：当 **Suggestions** 为空，或明确写明「无进一步建议 / 已达标」时，结束循环；不得在未复审的情况下宣称完成。

## 输入解析

从 `{{input}}` 提取（缺失时向用户确认一项即可，勿连环追问）：

| 项 | 说明 |
| -- | ---- |
| 技能意图 | 解决什么问题、谁在用、典型输入输出 |
| 技能名 | 小写连字符目录名，如 `my-helper`；未给出则从意图推导并告知用户 |

目标技能的**存放位置**由 skill-forge 与当前安装环境决定（新建或更新已有同名技能时，按 skill-forge 规则跳过初始化）。

## 执行流程

反复 **步骤 2 → 步骤 3** 直至满足退出条件；**步骤 1** 仅在首轮执行（或用户要求从头重做时执行）。

### 步骤 1 — skill-forge ⚠️ 首轮必做

1. 调用已安装技能 **skill-forge**，以 `{{input}}` 为需求来源，完整执行其工作流，至少包括：
   - 理解技能（≥3 个使用示例与触发关键词）
   - 规划架构（`scripts/` / `references/` / `assets/`、渐进加载）
   - 新技能时按 skill-forge 约定初始化；已存在则迭代更新
   - description（keyword bombing）、`SKILL.md` 正文、资源与交付前自检
2. 记录**目标技能名**及其**技能根目录**（供步骤 2、3 使用）。
3. 向用户简要说明技能名与用途（除非 `{{input}}` 要求先确认，否则可进入步骤 2）。

### 步骤 2 — skill-review ⚠️ 每轮必做

1. 调用已安装技能 **skill-review**。
2. 将审查目标固定为步骤 1 的**目标技能根目录**（仅该技能，非全仓库）。
3. 按 skill-review 执行分析并输出报告（中文），必须包含：
   - **Strengths**
   - **Suggestions**（按影响排序；每条含 What / Where / Fix）
4. 可选：将报告副本保存到 `.review/skill-<技能名>-{时间}.md`。

### 步骤 3 — 按 Suggestions 修复

- 逐条处理 **Suggestions**，仅修改**目标技能**内对应文件。
- 不要处理 Strengths 中的「可选优化」，除非其同时出现在 Suggestions。
- 修复后 **必须** 回到步骤 2 重新审查同一技能，不得跳过复审。

### 退出与收尾

当步骤 2 的 **Suggestions** 无任何待处理条目时：

1. 向用户输出：目标技能名、技能根目录、最终 Strengths 摘要、最后一轮「无 Suggestions」说明。
2. 若 skill-forge 提供打包流程且用户未禁止，按 **skill-forge** 技能内的打包说明执行（非本命令必做项）。

## 常见错误

| 问题 | 处理 |
| ---- | ---- |
| 未检测技能就执行 | 回到前置检查 |
| 用仓库内 `skills/*` 或本地路径代替调用 | 改为调用已安装 skill-forge / skill-review |
| 未读 skill-forge 就写 SKILL.md | 回到步骤 1，按 forge 清单补齐 |
| 审查整个仓库 | 步骤 2 仅针对目标技能根目录 |
| 根据 Strengths 做大范围重写 | 只落实 Suggestions |
| Suggestions 未清空就结束 | 继续步骤 2 → 3 |
| 技能名与目录不一致 | 以 `SKILL.md` frontmatter `name` 与技能目录名一致为准 |

## 完成前自检

- [ ] skill-forge、skill-review 安装检查已通过
- [ ] 目标技能已由 skill-forge 创建/更新且通过其 Pre-Delivery Checklist
- [ ] 至少经历一轮完整的 skill-review 报告（含 Strengths + Suggestions）
- [ ] 最终一轮 **Suggestions** 为空或明确无进一步建议
- [ ] 所有已处理的 Suggestion 均在复审中消失或已说明为何不适用
- [ ] 未在提示词中依赖「项目内 skills 路径」代替已安装技能
