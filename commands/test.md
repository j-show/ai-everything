# 检索实现代码，并重新实现测试用例

以下用语与用户需求一致，作为本技能的工作目标表述：

检索实现代码，并重新实现测试用例

如果用户 `{{input}}` 中指定了目录名，则只根据指定目录进行测试用例重写，否则重写所有测试用例。

## 原则（必须遵守）

- **以实现为准**：断言与夹具必须反映当前源码行为，而不是旧测试或记忆。
- **先定位再动笔**：未读完相关实现与调用链前，不重写大量测试。
- **最小有效覆盖**：优先行为与边界；删除仅重复实现细节或已失效的用例。

## 工作流

### 1. 检索实现

- 用语义搜索与精确搜索结合：模块名、符号、路由、错误文案、配置键。
- 打开入口（HTTP handler、CLI、公开 API）沿调用链向内追到核心逻辑。
- 记录：输入/输出类型、副作用（I/O、时钟、随机）、并发与错误分支。

### 2. 建立“当前契约”清单

用简短条目列出对外可见行为（正常路径、错误码、空值、幂等等），作为测试必须对齐的检查表。

### 3. 重新实现测试用例

- **替换优于修补**：与实现明显不一致的用例，整段重写比逐断言打补丁更清晰。
- **隔离不稳定因素**：对时间、网络、文件系统使用项目已有模式（fake、fixture、依赖注入）。
- **命名与结构**：与被测模块目录对齐；每个用例只验证一条行为或一条错误路径。

### 4. 验证

- 运行与改动范围匹配的测试命令（单文件、单目录或全量，按仓库惯例）。
- 若失败：先区分是测试错误还是实现缺陷；本技能默认优先让测试描述**真实**行为；若实现明显错误，向用户说明再决定是否改实现。

## 自检清单

- [ ] 已定位到权威实现（非仅类型定义或注释）。
- [ ] 测试断言与实现中的分支一一对应或可解释地省略。
- [ ] 无复制粘贴实现细节到断言中导致脆弱耦合（除非有意测字面协议）。
- [ ] 测试在 CI 本地等价环境中通过。

## 常见错误

| 问题                     | 处理                               |
| ------------------------ | ---------------------------------- |
| 只读测试推断行为         | 回到步骤 1，从实现建立契约         |
| 保留已删 API 的用例      | 删除或改为新 API 的等价场景        |
| 过度 mock 导致测不到集成 | 在单元与较浅集成之间按项目习惯取舍 |
