# 例子

只在控制流拿不准时读取对应小节。例子用来核对走向，不把其中的句子抄进产物。

## 多件缺陷

输入：「修一下：订单列表一直转圈，另外结算金额比购物车多 1 元。」

只问一次本轮 `dd-id` 覆盖哪一件。用户选列表转圈后，`dd-id` 为 `dd-2026-10-22-order-list-spinner`（日期用本轮开始那天）。金额另开一轮，不写进同一份 requirement.md。

## 名称收不成

输入：「修一下那个问题。」

现象不足以收成唯一 feature-name。只问一次这次修哪一个缺陷。用户回答「订单列表转圈」后采用 `dd-2026-10-22-order-list-spinner`。

## 子代理

输入：「按需求修：连续失败 5 次后仍允许再试。」

requirement.md 已澄清后询问是否创建子代理。用户回答是：一个子代理拿到 `dd-id`、requirement.md 路径、已编号行为原文和「非目标」原文。用户回答否：同一份编号列表在当前会话修复。两种回答都不修复「未决」、非目标或编号之外的行为。
