# 独立审查交接

由 reviewer 等外层编排独立审查时读取。单独调用 review-helper 仍沿用原有审查与修复流程，不强制依赖三个 Superpowers 技能。

## 输入

主代理在派发前解析并固定以下信息，审查代理不能重新选择更宽范围：

| 字段 | 内容 |
| --- | --- |
| 需求 | 已确认行为、验收依据及明确排除项；无法确认的假设单列 |
| 模式与权限 | 仅审查；不写文件、不修复、不暂存、不提交、不切分支、不派生代理 |
| 范围 | 路径过滤、排除项、文件清单、比较基线及选中的版本层 |
| 版本证据 | 提交层的固定 SHA；暂存层的 index 条目及差异；工作区/新增文件的内容或哈希清单及对应差异 |
| 验证 | 已运行命令、工作目录、对应版本、退出状态、覆盖和限制；尚未运行的检查 |
| 复审增量 | 原问题标识及原位置、处置依据、本轮实际修改、待确认项 |

不能仅给 BASE/HEAD 而漏掉已授权的未提交改动。多个版本层分别标注，不把重叠差异拼成虚构版本。不传完整对话或无关实现思考；派发前重新检查文件与标识一致。

审查期间内容变化时，受影响结论标为过期，由主代理重新固定内容并补审；不能把旧结论用于新内容。修复后的复审以当前工作区和本轮实际补丁为准，原快照保留作审计依据。

## 输出与处置

审查代理按 report-format.md 返回中文 P0–P3 发现，每项包含稳定标识、版本及真实位置、触发条件、影响、依据和建议；另列未覆盖行为和验证限制。不落盘报告，由主代理统一保存或仅在回复交付。

主代理核实反馈后维护：

```text
问题标识 → 成立待修复 → 已修复待复审 → 已关闭
         ├─ 不成立（反证）
         ├─ 待澄清（缺失信息或范围决定）
         └─ 阻塞（环境、冲突、无进展或未解决分歧）
```

关闭需修复证据、相关验证及复审支持；验证未完成时保留缺口，不能只凭改了文件关闭。仅审查模式保留发现而不修复。严重程度不授予额外权限；无关改进不进入自动修复。

复审依据原问题与新差异检查修复效果及引入的回归；不得把原暂存区仍有旧缺陷当成工作区修复失败。存在实质分歧且无法依据新证据解决时，记录双方依据并停止该项，不以更换 reviewer 刷取通过。
