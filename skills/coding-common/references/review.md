# 完成前自检

只在 Step 6 读取。对象是本次 diff。

## 严重级别

| 级别 | 含义 | 动作 |
| --- | --- | --- |
| CRITICAL | 安全漏洞或数据丢失 | 合并或完成前必须消除 |
| HIGH | 缺陷，或行为变化没有对应测试 | 完成前应当消除 |
| MEDIUM | 可维护性问题，包括说不出理由的源文件超过 800 行 | 不扩大范围时就修 |
| LOW | 风格偏好 | 用户要求整理风格时才改 |

## 清单

- [ ] 名字能看出用途
- [ ] 函数聚焦，大约短于 50 行
- [ ] 源文件内聚；超过 800 行时说明里写了原因
- [ ] 条件嵌套不超过 4 层
- [ ] 错误被显式处理
- [ ] 没有密钥或凭据字面量
- [ ] 没有只用于调试的打印
- [ ] 新行为有测试
- [ ] 项目有覆盖率命令时，结果不低于 80% 或项目自身门槛

安全敏感改动另以 `security.md` 的清单为准。在 diff 里查找：密钥字面量、字符串拼进查询、未编码就输出的外部输入、未规范化的文件路径、缺少身份或权限检查的保护操作。

## 性能问题

本次 diff 里出现下列情况时记为 HIGH；它们是查询或接口缺陷，不是提前优化：

- 循环里逐条访问存储，而一次批量读取就能得到同样的数据
- 可能返回无界结果的列表没有分页或上限
- 重复且昂贵的读取没有使用仓库里已有的缓存；仓库没有缓存时不要新造一层

## 完成判定

diff 里还有 CRITICAL 或 HIGH 时，先修再完成。只剩 MEDIUM 或 LOW 时可以完成；MEDIUM 在不扩大范围时修掉。
