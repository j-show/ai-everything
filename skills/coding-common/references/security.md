# 安全

只在 Step 1 把改动标为安全敏感时读取。核对本次 diff，并在被改文件中查找同一种写法。

## 改动清单

- [ ] 源码、测试和配置样例里没有密钥、口令或令牌字面量
- [ ] 用户输入、接口响应和文件内容在使用前已校验
- [ ] 查询使用参数绑定，不把外部字符串拼进查询
- [ ] 本次改动若输出页面或标记，内容已按该输出通道编码
- [ ] 本次改动若是会改变状态的 HTTP 入口，沿用仓库已有的跨站请求防护；仓库没有时在完成说明里记下缺口，不为此新装组件
- [ ] 受保护的操作同时检查身份和权限
- [ ] 本次改动若新增对外 HTTP 入口，沿用仓库已有的频率限制；仓库没有时在完成说明里记下缺口，不为此新装组件
- [ ] 返回给调用方的错误不含查询、路径、令牌或内部堆栈

## 密钥

- 密钥来自环境变量或仓库已有的密钥读取方式。
- 启动路径在缺少必需密钥时失败。
- 密钥一旦进入本次 diff，从 diff 中删除，并告诉用户需要轮换的密钥种类。回复、测试快照和日志里不写密钥值。

## 发现问题时的顺序

1. 停止继续加功能。
2. 先消除本次 diff 里的 CRITICAL 问题。
3. 在被改文件中查找拼接查询、未编码输出、未校验路径和硬编码密钥。
4. 修完后再回到功能实现。
